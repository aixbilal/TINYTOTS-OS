# TinyTots User Frontend — Contact

## Purpose

Provide reliable ways to contact TinyTots.

## Structure

Potentially:

```text
CONTACT HERO
↓
CONTACT OPTIONS
↓
FORM
↓
STORE / BUSINESS INFORMATION WHERE APPLICABLE
↓
FAQ / HELP LINK
```

Only display verified contact details.

## Form

Potential fields:

- name
- email/phone as required
- order reference when relevant
- topic
- message

Final fields depend on support workflow.

## Validation

Errors must be:

- local
- understandable
- actionable

## Success

After submission, communicate:

- successful receipt
- expected next step where verified
- reference number if the system provides one

## Spam / Abuse

The implementation should include appropriate backend protection.

## Accessibility

Form labels must be explicit.

## Motion

Minimal.

## Definition of Done

A customer knows exactly how to contact TinyTots and what happens after submitting a request.
