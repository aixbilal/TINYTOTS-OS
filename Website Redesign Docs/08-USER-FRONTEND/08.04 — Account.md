# TinyTots User Frontend — Account

## Purpose

The account page provides post-purchase and profile functionality.

## Core Areas

Depending on actual backend capabilities:

- overview
- orders
- order details
- profile
- addresses
- settings

## Signed-Out State

Provide a clear authentication path.

The page should explain the value of signing in without excessive marketing.

## Signed-In State

Prioritize:

1. recent orders
2. order status
3. account shortcuts

## Navigation

Desktop may use a side navigation.

Mobile should use a compact menu or stacked navigation.

## Order Cards

Show:

- order reference
- date
- status
- total
- action

## Empty Orders

Provide useful next action:

```text
No orders yet.
[Explore Products]
```

## Error States

Authentication/session problems must have explicit recovery.

## Motion

Minimal.

Account pages prioritize usability over cinematic effects.

## Definition of Done

A customer can access account information and order history without confusion.
