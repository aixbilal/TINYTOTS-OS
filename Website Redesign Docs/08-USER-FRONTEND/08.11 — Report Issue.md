# TinyTots User Frontend — Report Issue

## Purpose

Allow users to report website, product, order, or technical problems through a structured workflow.

## Issue Categories

Potential categories:

- Website problem
- Product issue
- Order issue
- Payment issue
- Account issue
- Other

Final categories must match the support workflow.

## Form

Possible fields:

- issue type
- description
- order reference where applicable
- contact information
- attachment where supported

## Evidence

If screenshots or attachments are supported, communicate:

- accepted formats
- size limitations
- privacy considerations

Do not claim support for an attachment workflow that does not exist.

## Validation

Make errors actionable.

## Success

Provide clear confirmation and a support reference if available.

## Security

Do not expose internal technical information.

## Motion

Minimal.

## Definition of Done

A user can report a problem without needing technical knowledge about the website.
