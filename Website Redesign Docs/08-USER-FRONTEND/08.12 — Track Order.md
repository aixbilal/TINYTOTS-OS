# TinyTots User Frontend — Track Order

## Purpose

Provide a fast path to order status without unnecessary navigation.

## Entry

Track Order may be accessible from:

- footer
- Help Center
- account
- order confirmation
- relevant emails/messages

## Input

The exact lookup method must follow the actual backend.

Potential inputs:

- order reference
- customer identifier
- authentication

Do not expose order information without appropriate verification.

## Status

Potential states:

```text
ORDER RECEIVED
→
PROCESSING
→
DISPATCHED
→
IN TRANSIT
→
DELIVERED
```

These labels are examples only. Final states must match the actual order system.

## Visual Treatment

Use a clear progress/status hierarchy.

Avoid unnecessary animation around shipment status.

## Error States

Examples:

- order not found
- invalid reference
- authentication required
- service unavailable

Each requires an actionable next step.

## Privacy

Never reveal sensitive order information to an unverified requester.

## Mobile

The status view must be easily scannable.

## Definition of Done

A customer can determine the current order status quickly and safely.
