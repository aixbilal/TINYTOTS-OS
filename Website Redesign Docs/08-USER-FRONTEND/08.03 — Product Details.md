# TinyTots User Frontend — Product Details

## Purpose

The Product Details page converts product interest into informed purchase intent.

## Primary Objectives

- present product accurately
- communicate price and variants
- support size selection
- explain product details
- enable purchase
- provide trust information

## Desktop Composition

Conceptually:

```text
MEDIA GALLERY        PRODUCT INFORMATION
                     ├── Name
                     ├── Price
                     ├── Description
                     ├── Variant
                     ├── Size
                     ├── Availability
                     └── Add to Cart
```

## Media

Primary product imagery must remain dominant.

Potential media:

- product photography
- alternate views
- detail images
- video
- optional 3D experience

## 3D

Only use 3D when a meaningful asset and use case exist.

The purchase path must work without it.

## Product Information

Do not hide essential information behind animation.

## Size

Size selection must be clear.

The Size Guide should be accessible without forcing the customer away from the product context unnecessarily.

## Purchase CTA

Primary CTA must be visually dominant and immediately understandable.

States:

- available
- unavailable
- processing
- added
- error

## Recommendations

Related products may appear below the primary purchase area.

They should not overpower the product itself.

## Trust Information

Potential information:

- shipping
- returns
- care
- support

Only display verified policies.

## Motion

Use motion to clarify:

- image changes
- selection
- add-to-cart feedback

Not to delay purchasing.

## Mobile

Recommended order:

```text
MEDIA
→
PRODUCT INFO
→
VARIANTS
→
SIZE
→
CTA
→
DETAILS
→
RECOMMENDATIONS
```

## Definition of Done

A customer can understand the product and complete the add-to-cart action without unnecessary friction.
