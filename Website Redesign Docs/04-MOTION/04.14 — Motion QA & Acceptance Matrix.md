# TinyTots Motion QA & Acceptance Matrix

## 1. Purpose

Every significant animation must be evaluated consistently.

## 2. QA Record

For each effect record:

```text
FEATURE
PAGE
TRIGGER
TECHNOLOGY
DURATION
EASING
MOBILE BEHAVIOR
REDUCED MOTION
FALLBACK
PERFORMANCE RISK
STATUS
```

## 3. Visual Questions

- Does it improve hierarchy?
- Does it feel premium?
- Does it fit the brand?
- Does it distract?
- Does it make the site feel slower?

## 4. UX Questions

- Is the interaction predictable?
- Can it be interrupted?
- Can it be operated without a mouse?
- Does it work on touch?
- Is state understandable without motion?

## 5. Performance Questions

- Does it use compositor-friendly properties?
- Does it trigger excessive rendering?
- Does it load unnecessary assets?
- Does it run continuously?
- Does it degrade correctly?

## 6. 3D Questions

- Is 3D justified?
- Is fallback implemented?
- Is mobile behavior acceptable?
- Is reduced motion handled?

## 7. Approval Status

Use:

- `candidate`
- `prototype`
- `testing`
- `approved`
- `rejected`
- `needs-revision`

## 8. Definition of Done

Phase 04 is complete when:

- motion tokens exist
- choreography rules exist
- page transitions are defined
- scroll rules exist
- microinteractions exist
- experimental effects have governance
- 3D has an approval gate
- accessibility behavior is defined
- performance budgets are defined
- QA criteria are defined
