# TinyTots Motion Performance Budget

## 1. Purpose

Premium visual quality cannot justify an unresponsive website.

## 2. Preferred Properties

Prefer animating:

- transform
- opacity

Use layout-affecting properties only when necessary.

## 3. Continuous Animation

Every continuous animation must have a reason.

Examples:

- live state
- campaign atmosphere
- carefully controlled hero motion

Decorative infinite motion should be rare.

## 4. Asset Budget

Large animation features must document:

- JavaScript cost
- image/model cost
- texture cost
- runtime behavior
- mobile behavior

## 5. Lazy Loading

Non-critical animation assets should load only when needed.

## 6. Viewport

Do not initialize heavy effects far outside the viewport.

## 7. Interaction

Animations must not delay:

- navigation
- search
- cart
- checkout
- admin operations

## 8. Failure

If an effect fails to load, the content must remain usable.

## 9. Testing Matrix

At minimum:

```text
HIGH-END DESKTOP
MID-RANGE LAPTOP
MOBILE
SLOW NETWORK
REDUCED MOTION
```

## 10. Acceptance Criteria

A motion feature is not complete until it passes both visual and performance review.
