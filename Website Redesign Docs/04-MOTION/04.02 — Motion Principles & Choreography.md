# TinyTots Motion Principles & Choreography

## 1. Choreography

Motion should have hierarchy.

Example:

```text
PAGE ENTER
  ↓
NAVIGATION
  ↓
HERO IMAGE
  ↓
HERO TYPE
  ↓
PRIMARY ACTION
```

Do not animate every object simultaneously.

## 2. Entrance

Preferred entrance behaviors:

- fade
- translate
- clip reveal
- mask reveal
- image scale settling

## 3. Exit

Exit animation should usually be shorter than entrance animation.

The user should never feel trapped waiting for a transition.

## 4. Sequencing

Stagger only when it improves comprehension.

Avoid long sequential animations for product grids.

## 5. Physicality

Motion may borrow from physical principles:

- inertia
- friction
- momentum
- soft settling

But the result must remain restrained.

## 6. Interruptibility

Animations should tolerate:

- rapid navigation
- repeated hover
- scrolling
- resize
- route changes

## 7. Scroll

Scroll-linked animation must not make ordinary browsing feel slow.

Prefer subtle relationships such as:

- image movement
- reveal
- scale
- opacity
- typography tracking

## 8. Stillness

After an animation completes, the interface should settle cleanly.

Avoid perpetual micro-motion unless it communicates live status.

## 9. Motion as Hierarchy

Large movement is reserved for:

- hero
- major campaign
- page transition
- exceptional interaction

Small movement is for:

- buttons
- cards
- icons
- controls

## 10. Acceptance Criteria

If removing an animation makes the interface clearer and equally premium, the animation should probably be removed.
