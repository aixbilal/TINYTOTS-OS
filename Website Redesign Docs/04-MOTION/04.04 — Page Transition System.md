# TinyTots Page Transition System

## 1. Purpose

Route changes may use subtle transitions to create continuity.

## 2. Preferred Pattern

```text
CURRENT PAGE
    ↓
CONTENT EXIT
    ↓
ROUTE CHANGE
    ↓
NEW PAGE ENTER
```

The transition must never delay navigation unnecessarily.

## 3. Transition Types

### Minimal

Crossfade or opacity transition.

### Editorial

Image/text continuity.

### Campaign

More cinematic transition when justified.

## 4. Shared Elements

Navigation and persistent UI should preferably remain visually stable.

## 5. Product Navigation

Moving from:

```text
PLP → PDP
```

may use a visual continuity technique based on the product image if implementation complexity remains reasonable.

## 6. Mobile

Mobile transitions must remain lightweight.

## 7. Failure Handling

If route loading is slow, the transition must not hide the fact that the application is waiting.

Use loading feedback where appropriate.

## 8. Accessibility

Users with reduced motion should receive an immediate or near-immediate state change.

## 9. Acceptance Criteria

Navigation must feel faster or equal to a non-animated implementation.
