# TinyTots Design System — Forms & Inputs

## 1. Purpose

Forms must feel premium without sacrificing speed or clarity.

## 2. Input Anatomy

```text
LABEL
INPUT
HELP / VALIDATION
```

## 3. States

Every input must define:

- default
- hover
- focus
- filled
- error
- disabled
- read-only
- loading where applicable

## 4. Labels

Do not rely on placeholder text as the only label.

## 5. Validation

Errors should:

- explain the problem
- identify the field
- provide correction guidance
- preserve entered information where possible

## 6. User Forms

Examples:

- account
- contact
- issue report
- checkout-related forms

## 7. Admin Forms

Admin forms may use denser layouts but must preserve clear hierarchy.

## 8. Motion

Validation transitions should be subtle.

Avoid dramatic movement when a user has made an error.

## 9. Accessibility

Use:

- semantic labels
- keyboard support
- correct focus
- accessible errors
- appropriate input types

## 10. Acceptance Criteria

A user can complete a form without needing to infer what a control means.
