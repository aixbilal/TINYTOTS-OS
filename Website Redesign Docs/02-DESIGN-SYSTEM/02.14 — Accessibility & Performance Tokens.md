# TinyTots Design System — Accessibility & Performance

## 1. Purpose

Accessibility and performance are system requirements, not QA afterthoughts.

## 2. Focus

All interactive controls must have a visible focus treatment.

Do not remove browser focus without replacing it with an accessible equivalent.

## 3. Reduced Motion

The system must respect:

```css
@media (prefers-reduced-motion: reduce)
```

Reduced motion should:

- remove unnecessary parallax
- reduce transform movement
- disable decorative loops
- shorten or remove nonessential transitions

Core state changes must remain understandable.

## 4. Contrast

All semantic color combinations must be tested.

Do not approve final color tokens without contrast verification.

## 5. Touch

Interactive targets must be large enough for reliable touch interaction.

## 6. Keyboard

Users must be able to:

- navigate
- activate controls
- close overlays
- use forms
- access navigation
- operate critical functionality

without a mouse.

## 7. Images

Use:

- responsive image sizing
- modern formats where supported
- appropriate dimensions
- lazy loading where appropriate
- eager loading only for critical above-the-fold assets

## 8. Animation

Animation must not:

- block interaction
- cause excessive layout work
- create persistent CPU/GPU load
- cause content to shift unexpectedly

## 9. 3D/WebGL

3D must be treated as a progressive enhancement.

Fallback hierarchy:

```text
3D
↓
animated 2D
↓
static image
```

The page must remain functional at every level.

## 10. Performance Review

Major animated features should document:

- estimated asset cost
- runtime cost
- mobile behavior
- fallback
- reduced-motion behavior

## 11. Acceptance Criteria

A design is not production-ready until accessibility and performance behavior are specified.
