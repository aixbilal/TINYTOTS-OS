# TinyTots Design System — Buttons & Controls

## 1. Button Hierarchy

Define:

### Primary

Most important action.

### Secondary

Supporting action.

### Tertiary

Low-emphasis action.

### Destructive

Irreversible/dangerous action.

## 2. User Frontend

Primary actions may use the brand accent or high-contrast neutral depending on context.

## 3. Admin

Admin primary actions should prioritize clarity and status.

## 4. Shape

Buttons should be refined, not overly bubbly.

## 5. States

Every interactive control must define:

```text
default
hover
focus
active
disabled
loading
success/error where applicable
```

## 6. Motion

Preferred microinteraction:

```text
rest
→ slight visual response
→ active state
→ settle
```

Avoid exaggerated scale.

## 7. Magnetic Buttons

Magnetic behavior may be considered for selected hero/marketing CTAs.

It is not a default button behavior.

Must support:

- touch devices
- reduced motion
- keyboard interaction

## 8. Gooey / Blob Effects

Gooey effects are considered decorative experimental patterns.

They must not be used for:

- critical navigation
- forms
- accessibility-critical controls
- repeated everyday actions

## 9. Inputs

Inputs require:

- label
- placeholder where useful
- focus
- error
- disabled
- loading if applicable
- validation feedback

## 10. Acceptance Criteria

A user must understand which action is primary without animation.
