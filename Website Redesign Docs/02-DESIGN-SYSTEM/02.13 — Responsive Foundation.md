# TinyTots Design System — Responsive Foundation

## 1. Principle

Responsive behavior is part of the component design, not an afterthought.

## 2. Device Classes

Design and test:

- small mobile
- large mobile
- tablet
- laptop
- desktop
- wide desktop

Exact breakpoint values should be defined during implementation based on the existing stack and content.

## 3. Layout

Components may change:

- columns
- alignment
- density
- order
- navigation
- image crop
- typography scale

## 4. Mobile

Do not simply reduce desktop dimensions.

Explicitly define:

- mobile navigation
- touch targets
- stacked sections
- product grid
- CTA behavior
- image ratios
- text wrapping

## 5. Tablet

Tablet may use intermediate compositions rather than simply choosing desktop/mobile.

## 6. Wide Desktop

Do not allow content to stretch indefinitely.

Use maximum content widths.

## 7. Motion

Reduce motion complexity on low-powered devices when appropriate.

## 8. 3D

3D experiences must have:

- static fallback
- reduced-motion fallback
- mobile strategy
- performance strategy

## 9. Acceptance Criteria

No critical functionality may depend exclusively on desktop interaction.
