# TinyTots Design System — Spacing & Layout Grid

## 1. Philosophy

Spacing is one of the primary mechanisms for perceived quality.

The system should feel generous without wasting space.

## 2. Base Unit

Use a consistent spacing scale based on a small mathematical unit.

A 4px or 8px-derived scale may be evaluated during implementation.

Do not create arbitrary values for individual sections.

## 3. Semantic Spacing

Use:

```text
space-1
space-2
space-3
space-4
space-5
space-6
space-7
space-8
space-9
space-10
```

Exact production values are finalized during token implementation.

## 4. Layout Widths

Define semantic containers:

- `container-reading`
- `container-content`
- `container-wide`
- `container-full`

## 5. Grid

User frontend should support:

- editorial grid
- product grid
- content grid
- asymmetric compositions

Admin should support:

- navigation rail/sidebar
- content area
- data grid
- form layouts

## 6. Desktop

Desktop layouts should use whitespace to establish hierarchy.

Do not maximize content density simply because screen width is available.

## 7. Mobile

Mobile should prioritize:

1. content hierarchy
2. touch usability
3. readable typography
4. image impact
5. efficient navigation

## 8. Section Rhythm

Sections should not all have identical vertical spacing.

Use rhythm deliberately:

```text
quiet → visual → product → quiet → editorial → action
```

## 9. Alignment

Use shared alignment anchors.

Examples:

- page heading edge
- product grid edge
- navigation edge
- content column edge

## 10. Asymmetry

Asymmetry is allowed when intentional.

It must still respect an underlying grid.

## 11. Full Bleed

Full-bleed sections may escape the content container.

Use for:

- hero
- campaign
- editorial photography
- major transitions

## 12. Acceptance Criteria

Spacing must be traceable to system tokens or documented exceptions.
