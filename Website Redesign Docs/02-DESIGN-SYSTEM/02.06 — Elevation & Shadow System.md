# TinyTots Design System — Elevation & Shadow

## 1. Philosophy

Elevation should be subtle.

The system should not look like a stack of floating cards.

## 2. Levels

Define:

```text
elevation-none
elevation-subtle
elevation-raised
elevation-floating
```

## 3. Appropriate Uses

### Subtle

- hover states
- small cards
- controls

### Raised

- dropdowns
- popovers
- selected floating content

### Floating

- modal
- important overlay
- command/search interface

## 4. Avoid

- large permanent shadows
- glowing shadows
- colored shadows without brand justification
- shadows on every card

## 5. Dark Surfaces

Dark sections should not depend on heavy shadow to establish hierarchy.

Use contrast and spacing.

## 6. Glass/Blur

Blur may be used selectively for:

- navigation overlays
- contextual panels
- premium transition moments

It must not become the default component treatment.

## 7. Performance

Avoid expensive backdrop filters when simpler opacity/solid surfaces achieve the same result.

## 8. Acceptance Criteria

Every elevation level must have a clear semantic use.
