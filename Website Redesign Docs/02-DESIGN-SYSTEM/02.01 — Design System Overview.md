# TinyTots Design System — Overview

## Purpose

This document establishes the architecture of the TinyTots visual and interaction system.

The design system must make the site feel like one product rather than a collection of individually designed pages.

## System Layers

```text
BRAND
  ↓
FOUNDATION TOKENS
  ↓
COMPONENT TOKENS
  ↓
COMPONENTS
  ↓
PATTERNS
  ↓
PAGE COMPOSITIONS
  ↓
USER / ADMIN EXPERIENCES
```

## Core Layers

### Brand

Defines:

- positioning
- personality
- emotional direction
- visual territory

Source:

`01-BRAND`

### Foundation Tokens

Defines:

- color
- typography
- spacing
- sizing
- radius
- borders
- shadows
- motion

### Components

Defines reusable:

- buttons
- inputs
- navigation
- cards
- product components
- tables
- dialogs
- feedback states

### Patterns

Defines reusable combinations such as:

- product discovery
- filters
- campaign hero
- editorial split
- admin CRUD
- status management

### Pages

Pages compose approved components and patterns.

Pages must not independently invent foundational styling.

## Design System Priorities

1. consistency
2. accessibility
3. readability
4. responsiveness
5. performance
6. brand expression
7. visual novelty

## User vs Admin

Both experiences share:

- color tokens
- typography tokens
- spacing foundations
- icon principles
- interaction states
- motion foundations

They differ in:

- density
- layout patterns
- content hierarchy
- animation intensity

## Naming

Tokens should use semantic names.

Prefer:

`color.surface.default`

over:

`color.beigeLight`

Prefer:

`motion.duration.standard`

over:

`animation1`

## Acceptance Criteria

A developer must be able to identify the correct token/component without guessing.
