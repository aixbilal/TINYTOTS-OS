# TinyTots Design System — Color System

## 1. Color Philosophy

The palette should feel:

- warm
- sophisticated
- calm
- contemporary
- photographic

The color system must support premium children's fashion without becoming childish.

## 2. Palette Direction

The proposed foundation is a warm neutral architecture:

```text
LIGHT
Warm Ivory
  ↓
Soft Sand
  ↓
Warm Stone
  ↓
Muted Taupe
  ↓
Deep Charcoal
  ↓
Near Black
```

A restrained warm accent may be used for emphasis.

The exact production values must be approved after visual reference generation and contrast testing.

## 3. Semantic Roles

The implementation must use semantic roles rather than hard-coded color names.

### Surfaces

- `surface.canvas`
- `surface.primary`
- `surface.secondary`
- `surface.inverse`
- `surface.elevated`

### Text

- `text.primary`
- `text.secondary`
- `text.tertiary`
- `text.inverse`
- `text.disabled`

### Borders

- `border.subtle`
- `border.default`
- `border.strong`
- `border.inverse`

### Brand

- `brand.primary`
- `brand.secondary`
- `brand.accent`

### Feedback

- `feedback.success`
- `feedback.warning`
- `feedback.error`
- `feedback.info`

## 4. Accent Rule

The warm accent is not the default color for every interactive element.

Use accent for:

- important emphasis
- selected brand moments
- campaign-specific highlights
- important CTAs where appropriate

Do not use it indiscriminately.

## 5. Admin Color Usage

Admin should use a quieter version of the same system.

Status colors must remain semantically recognizable.

## 6. Contrast

All text and interactive elements must meet applicable WCAG contrast requirements.

Exact token values cannot be approved until contrast testing is performed.

## 7. Dark Sections

Dark sections may be used for:

- campaign transitions
- footer
- editorial contrast
- premium product storytelling

Dark mode is not automatically required as a full-site user theme.

## 8. Image Interaction

Do not apply heavy global overlays merely to force text contrast.

Prefer:

- correct image selection
- controlled crop
- localized gradient when required
- alternate text placement

## 9. Color Rules

Never introduce a new color directly inside a component without:

1. checking existing tokens
2. determining semantic role
3. documenting the exception if necessary

## 10. Future Deliverable

Final production color values must be recorded as:

```text
token
value
usage
contrast
user/admin scope
light/dark behavior
```
