## 1. Purpose and operating rules

This document is the single source of truth for asset production, filenames, storage locations, sequence, counts, and progress. It is formatted for reliable use in Obsidian, GitHub, ChatGPT, Claude, Gemini, and by human production teams.

- All paths are relative to the project root unless stated otherwise.
- The physical Windows folder names use `01 — Name`, not repeated hierarchical numbers such as `16.02.01`.
- IDs are permanent. Never reuse an ID for a different asset.
- Website-ready AI/generated imagery stays in `02 — Generated Images`.
- Real photographs, licensed source photographs, and original shoot files belong in `03 — Photography`.
- A generated image does not move into Photography merely because it looks photographic.
- `Generated / review pending` means the file has been produced but is not yet approved for production use.
- Requirement-driven items are made only when the design or implementation proves they are needed.
- Responsive derivatives retain the parent ID plus a suffix, such as `H01-M`, `H01-T`, `H01-2X`, or `H01-WEBP`; they do not receive unrelated new IDs.

### Phase 13 — Responsive and delivery variants

Responsive work happens after each master is approved, not as an uncontrolled final batch. Create only variants used by the implemented layouts.

Recommended suffix system:

| Suffix | Meaning | Example |
|---|---|---|
| `-D` | Desktop-specific export where needed | `H01-D — Homepage Master Hero Desktop.webp` |
| `-T` | Tablet-specific crop/composition | `H01-T — Homepage Master Hero Tablet.webp` |
| `-M` | Mobile-specific crop/composition | `H01-M — Homepage Master Hero Mobile.webp` |
| `-2X` | High-density raster export | `H01-D-2X — Homepage Master Hero Desktop.webp` |
| `-WEBP` / `-AVIF` | Delivery-format derivative when tracked separately | Preserve parent ID and descriptive name |

H03, C07, and V05 remain standalone IDs because they were explicitly planned as independently composed assets. Avoid duplicating them as generic `-M` derivatives.

For every approved master, verify:

- actual breakpoint and slot dimensions;
- art-directed crop and text-safe area;
- 1×/2× need;
- WebP/AVIF/JPEG/PNG/SVG choice;
- compression and visual quality;
- intrinsic dimensions and aspect ratio;
- meaningful alt text or decorative treatment;
- poster/fallback requirements for motion/3D.

## 7. Change control

This blueprint is locked. No new folder may be invented mid-production. If implementation exposes a genuine missing category:

1. document the need and why no existing destination works;
2. propose the exact folder name, location, ID convention, and migration impact;
3. update this blueprint first;
4. approve the change;
5. then create the folder and update `01 — Asset Inventory.md`.

This prevents folder drift, mismatched paths, lost assets, duplicate naming, and different AI tools or collaborators inventing incompatible structures.
