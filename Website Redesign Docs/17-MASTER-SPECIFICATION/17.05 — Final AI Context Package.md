# Final AI Context Package

## Purpose

Provide a compact, high-value context package for AI agents working on the TinyTots website.

This document is designed to reduce repeated context loading while preserving the project's critical constraints.

---

# 1. Project

TinyTots is a premium kidswear omnichannel platform with:

- customer-facing website
- administrative frontend
- Electron POS
- WhatsApp/integration systems
- Supabase-backed data architecture

This package concerns the web redesign.

---

# 6. Technical Principle

The live repository is the implementation source of truth.

Do not invent:

- routes
- components
- APIs
- database fields
- dependencies
- asset paths
- existing functionality

Inspect before editing.

---

# 9. AI Rules

AI agents must:

- investigate before editing
- reuse existing components where appropriate
- follow approved design tokens
- avoid unnecessary dependencies
- preserve existing functionality
- respect accessibility
- respect performance
- implement responsive behavior
- provide fallbacks for advanced effects
- report validation honestly

AI agents must not:

- fabricate repository facts
- silently change architecture
- introduce random visual styles
- add animation everywhere
- make 3D mandatory
- claim tests passed when they were not run

---

# 10. Motion Rule

Motion is purposeful.

Use it for:

- feedback
- hierarchy
- continuity
- discovery
- transitions

Prefer restraint over spectacle.

Respect reduced motion.

---

# 11. 3D Rule

3D is progressive enhancement.

```text
NO WEBGL
→ FULL CORE EXPERIENCE

WEBGL
→ ENHANCED EXPERIENCE
```

Never make 3D required for shopping.

---

# 12. Performance Rule

Premium does not mean heavy.

Prioritize:

```text
CORE CONTENT
↓
PRODUCT EXPERIENCE
↓
INTERACTION
↓
ENHANCEMENT
```

Lazy-load non-critical heavy systems.

---

# 13. Accessibility Rule

Every critical journey must remain usable through:

- keyboard
- touch
- accessible forms
- visible focus
- semantic structure
- reduced motion

# 19. Final AI Principle

The AI should behave as an implementation partner, not an autonomous redesign authority.

```text
DOCUMENTATION
defines approved direction

REPOSITORY
defines actual implementation reality

HUMAN
approves significant decisions

AI
investigates, implements, validates, and reports
```

When uncertainty exists, investigate it.

When a requirement conflicts with the repository, report the conflict.

When an effect harms usability or performance, simplify it.

When a design decision is already documented, follow it instead of inventing a new one.
