# TinyTots Web Design — AI Operating Protocol

## 1. Purpose

This protocol defines how ChatGPT, Gemini, Claude Code, Obsidian, and GitHub work together.

The goal is to reduce duplicated repository analysis, preserve context, and prevent AI agents from making unsupported assumptions.

## 2. Tool Roles

### ChatGPT

Primary role:

**Creative Director + Design Documentation Architect**

Use for:

- design strategy
- design decisions
- architecture of documentation
- evaluating alternatives
- resolving conflicts
- approving principles
- converting research into durable specifications

### Gemini

Primary role:

**Repository Analyst + Visual Research/QA Assistant**

Use for:

- repository mapping
- file discovery
- dependency analysis
- screenshot analysis
- visual comparisons
- targeted reports
- high-volume research
- asset/reference exploration

Gemini reports are evidence, not final authority.

### Claude Code

Primary role:

**Lead Implementation Agent**

Use for:

- repository implementation
- frontend architecture
- component work
- animation implementation
- responsive implementation
- refactoring
- tests and fixes
- translating approved specifications into code

### Obsidian

Primary role:

**Persistent Knowledge Base**

Use for:

- approved documentation
- decisions
- references
- specifications
- project status
- links between documents

### GitHub

Primary role:

**Code Source of Truth**

Use for:

- source code
- branches
- commits
- pull requests
- implementation history

## 3. Repository Investigation Protocol

Do not begin large coding tasks with unrestricted repository exploration unless necessary.

Instead:

### Step 1

Define the task.

### Step 2

Ask for required repository context.

### Step 3

Use Gemini to identify:

- relevant files
- exact paths
- related components
- dependencies
- assets
- styles
- APIs
- configuration

### Step 4

Give the targeted report to Claude Code.

### Step 5

Claude starts from the targeted scope.

### Step 6

Claude may expand scope when dependencies require it.

The targeted scope is a starting point, not a blindfold.

## 4. Claude Code Operating Rules

Before modifying code:

1. read the relevant design specification
2. inspect the targeted repository files
3. identify dependencies
4. produce a change plan
5. identify affected files
6. identify potential regressions
7. implement only after the plan is understood

Do not:

- rewrite unrelated systems
- replace libraries without justification
- remove existing functionality for aesthetics
- invent backend behavior
- hardcode content that belongs to the CMS
- introduce animation libraries unnecessarily

## 5. Gemini Report Requirements

A repository investigation report should include:

```text
TASK
CURRENT BEHAVIOR
FILES REQUIRED
EXACT PATHS
COMPONENT RELATIONSHIPS
STYLE SOURCES
ASSET SOURCES
DATA/API SOURCES
DEPENDENCIES
RISKS
UNKNOWN INFORMATION
RECOMMENDED INSPECTION ORDER
```

## 6. Design-to-Code Protocol

Every implementation task should contain:

```text
DESIGN SPECIFICATION
CURRENT BEHAVIOR
TARGET BEHAVIOR
FILES TO INSPECT
FILES LIKELY TO CHANGE
DO NOT CHANGE
FUNCTIONAL CONSTRAINTS
VISUAL REQUIREMENTS
MOTION REQUIREMENTS
RESPONSIVE REQUIREMENTS
ACCESSIBILITY REQUIREMENTS
PERFORMANCE REQUIREMENTS
ACCEPTANCE CRITERIA
```

## 7. Visual QA Protocol

After implementation:

1. capture screenshots
2. compare against approved specification
3. use Gemini for structured visual analysis
4. classify findings
5. return actionable issues to Claude
6. re-test

Visual QA should not become an uncontrolled redesign loop.

## 8. Change Classification

Every implementation change should be classified:

`DESIGN`
`UX`
`COMPONENT`
`ANIMATION`
`RESPONSIVE`
`PERFORMANCE`
`ACCESSIBILITY`
`BUGFIX`
`REFACTOR`

## 9. AI Handoff Format

Use:

```text
CONTEXT
TASK
SOURCE DOCUMENTS
REPOSITORY FILES
CURRENT STATE
TARGET STATE
CONSTRAINTS
ACCEPTANCE CRITERIA
OUTPUT REQUIRED
```

## 10. AI Memory Strategy

Do not depend on conversation history as the only source of project context.

Important knowledge must be written to:

- Obsidian documentation
- repository context files where appropriate
- Git history

## 11. Context Efficiency Rule

Large repositories should be investigated progressively.

Do not repeatedly provide:

- entire source trees
- irrelevant files
- duplicated documentation
- obsolete reports

Use targeted context packages.

## 12. No Autonomous Scope Expansion

An AI agent may discover related work, but it must not silently expand the task.

Example:

If asked to redesign the homepage, it may discover that Header changes are required.

It should report:

> Header is a shared dependency and requires modification.

It should not silently redesign:

- checkout
- account
- admin
- backend
- unrelated pages

## 13. Final Human Approval Points

Human approval is required for:

- brand direction
- major design-system changes
- major navigation changes
- introducing a major dependency
- introducing 3D
- removing existing functionality
- changing business behavior
- changing architecture beyond task scope

## 14. AI Quality Rule

The preferred AI behavior is:

> inspect → verify → plan → implement → test → report

not:

> guess → generate → hope.
