# Browser Support

## Purpose

Define progressive enhancement and compatibility expectations for the TinyTots redesign.

## Primary Target

The website should prioritize current mainstream browsers used by customers.

Primary categories:

- Chromium-based browsers
- Safari
- Firefox
- current mobile browsers

Exact minimum versions should be confirmed against deployment analytics before finalizing a hard support matrix.

## Progressive Enhancement

The baseline experience must work without depending on:

- WebGL
- advanced animation APIs
- experimental browser features

Advanced capabilities should enhance the baseline.

## Browser Feature Strategy

For unsupported features:

```text
DETECT
↓
USE ENHANCED EXPERIENCE IF SUPPORTED
↓
OTHERWISE USE FALLBACK
```

Do not assume feature support from browser brand alone.

## Mobile Safari

Pay particular attention to:

- viewport behavior
- fixed positioning
- touch scrolling
- video behavior
- memory pressure
- WebGL performance
- animation performance

## Chromium

Validate:

- layout
- fonts
- animation
- WebGL
- input behavior

## Firefox

Validate:

- layout
- typography
- filters
- animation
- WebGL
- form behavior

## Graceful Degradation

If an advanced effect fails, the user should still be able to:

- navigate
- search
- browse products
- view product details
- add to cart
- checkout
- access account functionality

## Testing Matrix

At minimum test:

```text
DESKTOP
Chrome / Edge / Safari / Firefox

MOBILE
iOS Safari
Android Chromium

ENHANCED
WebGL-capable device

FALLBACK
WebGL-disabled / reduced-motion environment
```

## AI Rule

Never use browser-specific hacks without documenting:

1. the browser issue,
2. why the workaround is necessary,
3. what browsers are affected,
4. how it can eventually be removed.
