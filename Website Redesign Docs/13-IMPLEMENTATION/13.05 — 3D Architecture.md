# 3D Architecture

## Purpose

Define how Three.js / React Three Fiber experiences are isolated, performant, and progressively enhanced.

## Core Principle

3D is optional.

```text
CORE EXPERIENCE
=
FULLY FUNCTIONAL WITHOUT WEBGL
```

3D enhances the experience but must never be a single point of failure.

## Architecture

Preferred conceptual structure:

```text
PAGE
 ↓
3D EXPERIENCE WRAPPER
 ↓
CAPABILITY CHECK
 ↓
WEBGL EXPERIENCE
 ↓
FALLBACK EXPERIENCE
```

## Separation

Keep 3D code isolated from normal UI whenever possible.

Suggested conceptual areas:

```text
components/3d/
lib/3d/
assets/3d/
```

Exact paths must follow the actual repository architecture.

## React Three Fiber

Use React Three Fiber when React integration and declarative scene composition provide meaningful benefits.

## Three.js

Use direct Three.js when lower-level control is required and the added complexity is justified.

## Loading

3D assets should be:

- lazy-loaded
- compressed
- loaded only when needed
- progressively introduced

## Mobile

Mobile must receive an intentional experience.

Do not simply send desktop-quality WebGL to low-power devices.

## Reduced Motion

3D animation must respond appropriately to reduced-motion preferences.

## Failure States

Handle:

- unsupported WebGL
- asset loading failure
- network failure
- low-performance devices
- user preference disabling motion

## AI Rule

Never add 3D to a section unless the design documentation identifies its purpose.
