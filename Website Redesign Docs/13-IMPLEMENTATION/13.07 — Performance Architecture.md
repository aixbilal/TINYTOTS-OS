# Performance Architecture

## Purpose

Define performance as a first-class design constraint.

A premium website that feels slow is not premium.

## Core Principle

```text
VISUAL QUALITY
+
INTERACTION QUALITY
+
PERFORMANCE
=
PREMIUM EXPERIENCE
```

## Critical Performance Areas

Monitor:

- initial document response
- LCP
- INP
- CLS
- JavaScript execution
- image weight
- font loading
- animation cost
- WebGL cost
- third-party scripts

## Loading Strategy

Prioritize:

```text
CRITICAL UI
↓
PRIMARY HERO
↓
ABOVE-FOLD CONTENT
↓
INTERACTION
↓
SECONDARY MEDIA
↓
3D / NON-CRITICAL EFFECTS
```

## Code Splitting

Lazy-load:

- heavy editors
- 3D
- complex animation modules
- rarely visited routes
- large third-party dependencies

## Images

Use:

- responsive sizing
- modern formats where supported
- appropriate compression
- lazy loading for below-fold media

Do not lazy-load critical hero media unnecessarily.

## Animation

Avoid:

- excessive blur
- large particle systems
- expensive layout animations
- continuous GPU-heavy effects
- unnecessary scroll listeners

## 3D

3D must have explicit performance budgets.

It must not delay the core shopping experience.

## Monitoring

Performance should be tested on:

- desktop
- mid-range mobile
- slower mobile/network conditions

## Acceptance Rule

If an effect materially damages usability or performance, remove or simplify the effect.

The design is not more important than the experience.
