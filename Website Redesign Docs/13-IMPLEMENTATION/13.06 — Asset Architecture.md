# Asset Architecture

## Purpose

Define how images, video, icons, fonts, 3D assets, and campaign media should be organized and delivered.

## Asset Categories

```text
PRODUCT
CAMPAIGN
EDITORIAL
BRAND
UI
ICON
FONT
VIDEO
3D
```

## Naming

Use predictable names based on:

```text
purpose
+
entity
+
variant
+
size/context
```

Avoid meaningless filenames.

## Product Assets

Product images should have predictable relationships between:

- product
- SKU
- variant
- image
- ordering

Do not duplicate assets unnecessarily.

## Responsive Images

Use appropriate responsive image behavior.

Avoid serving desktop-scale assets to small screens without reason.

## Image Quality

Optimize:

- dimensions
- format
- compression
- loading priority
- caching

## Hero Assets

Hero media should be treated differently from ordinary content because of its effect on initial loading.

Use:

- correct dimensions
- intentional focal points
- responsive variants
- controlled preload behavior

## 3D Assets

Keep 3D assets separate from ordinary images.

Track:

- format
- polygon complexity
- texture size
- compression
- expected device tier

## Fonts

Only load required weights and styles.

Avoid unnecessary font variants.

## Source of Truth

The repository and configured content system remain the authoritative sources for asset references.

Do not hardcode temporary generated asset URLs into production components.
