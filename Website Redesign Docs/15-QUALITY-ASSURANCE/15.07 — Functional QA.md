# Functional QA

## Purpose

Verify that the redesign preserves and correctly implements the actual shopping and account functionality.

Visual quality must never hide functional regressions.

## Primary Journeys

Test:

```text
HOME
→ PRODUCT DISCOVERY
→ PRODUCT DETAILS
→ CART
→ CHECKOUT
```

Also test:

```text
SEARCH
FILTERS
SORTING
ACCOUNT
ORDERS
TRACK ORDER
HELP
CONTACT
```

## Product

Verify:

- product listing
- product detail
- variants
- size selection
- availability
- imagery
- pricing
- add to cart

## Cart

Verify:

- add
- remove
- quantity
- totals
- persistence
- empty state

## Checkout

Verify:

- validation
- shipping
- payment flow
- error handling
- order creation
- confirmation

## Search

Verify:

- query input
- results
- no results
- loading
- clearing
- navigation to product

## Account

Verify:

- authentication
- profile
- order history
- account states
- sign-in/sign-out

## Error States

Test:

- network failure
- missing product
- unavailable item
- invalid input
- API failure
- empty results

## Regression Rule

Existing working functionality must remain functional unless the change explicitly modifies its behavior.

## Acceptance

All critical shopping journeys must pass end-to-end before final acceptance.
