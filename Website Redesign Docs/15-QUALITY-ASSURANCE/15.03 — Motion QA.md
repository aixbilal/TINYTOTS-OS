# Motion QA

## Purpose

Verify that animation supports the TinyTots experience rather than becoming visual noise.

## Core Test

Every significant animation should have a reason.

Ask:

> What does this movement communicate?

## Check

Verify:

- timing
- easing
- sequencing
- stagger
- interruption
- hover behavior
- scroll behavior
- page transitions
- loading transitions
- exit transitions

## Motion Hierarchy

```text
FUNCTIONAL
↓
EDITORIAL
↓
SIGNATURE
```

Signature animation should remain rare.

## Performance

Check for:

- dropped frames
- excessive CPU/GPU usage
- layout thrashing
- continuous expensive animation
- unnecessary scroll handlers

## Reduced Motion

Test with:

```text
prefers-reduced-motion: reduce
```

Verify that:

- functionality remains intact
- motion is reduced or removed appropriately
- important information is still communicated

## Failure Conditions

Reject animation that:

- delays critical actions
- causes disorientation
- obstructs content
- repeats unnecessarily
- exists only as decoration
- materially damages performance

## Acceptance

Motion should feel intentional, controlled, and consistent across the system.
