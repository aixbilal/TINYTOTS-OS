# Accessibility QA

## Purpose

Verify that the premium interface remains accessible to users with different abilities and interaction methods.

## Keyboard QA

Test the complete journey using keyboard only.

Verify:

- logical tab order
- visible focus
- menus
- search
- dialogs
- filters
- cart
- checkout
- account controls

## Screen Reader-Oriented QA

Check:

- page landmarks
- headings
- labels
- buttons
- links
- form errors
- dialog names
- dynamic state changes

## Contrast

Verify adequate contrast for:

- text
- controls
- borders where meaningful
- focus indicators
- important status information

## Forms

Check:

- labels
- instructions
- errors
- success states
- keyboard operation
- autocomplete where appropriate

## Motion

Test reduced-motion preferences.

## Touch

Verify important controls are practical to operate by touch.

## Semantic HTML

Check that visual styling has not replaced semantic meaning.

## 3D

Verify that essential information is available without 3D.

## Acceptance

No critical user journey should depend on inaccessible interaction, visual-only information, or animation.
