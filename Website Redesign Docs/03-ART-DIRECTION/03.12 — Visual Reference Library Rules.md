# TinyTots Visual Reference Library Rules

## 1. Purpose

The reference library prevents random visual inspiration from entering the design system.

## 2. Reference Categories

Maintain separate collections for:

- brand
- photography
- typography
- color
- layout
- navigation
- product
- motion
- 3D
- interaction
- admin

## 3. Reference Metadata

Each reference should record:

```text
TITLE
SOURCE
CATEGORY
WHAT TO STUDY
TINY TOTS APPLICATION
RISK
STATUS
```

## 4. Reference Status

Use:

- `candidate`
- `reviewed`
- `approved`
- `rejected`
- `archived`

## 5. Approved Reference

Approval means:

> the principle shown may influence the TinyTots design.

It does not mean:

> reproduce the reference.

## 6. External UI Libraries

Potential sources include:

- Vengeance UI
- Magic UI
- Forge UI
- Lore UI
- UIverse
- other interaction libraries

They must be evaluated by:

- visual fit
- accessibility
- performance
- responsiveness
- dependency cost
- maintainability
- originality

## 7. Reference Capture

When saving a reference, record the exact element being studied.

Bad:

> Nice website.

Good:

> Search overlay uses full-width transition, large type, recent searches, and restrained background blur.

## 8. Reference Pollution

Do not save references simply because they are visually impressive.

The library should remain curated.

## 9. Acceptance Criteria

Every approved reference must have an identifiable design principle that can be translated into a TinyTots rule.
