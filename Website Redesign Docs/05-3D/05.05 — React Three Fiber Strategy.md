# TinyTots React Three Fiber Strategy

## Purpose

React Three Fiber may be used as the React integration layer for selected Three.js experiences.

## When To Use

R3F is appropriate when:

- scene state interacts with React state
- reusable React-style 3D components are useful
- the experience belongs naturally inside a Next.js/React page

## When Not To Use

Avoid creating a React abstraction simply for a trivial static WebGL effect.

## Component Boundary

Recommended structure:

```text
components/
  3d/
    experience/
    scenes/
    objects/
    materials/
    controls/
    loaders/
```

Actual repository paths must follow the existing project conventions.

## Canvas

A Canvas should be treated as an expensive rendering surface.

Do not mount unnecessary canvases across the page.

## State

Separate:

```text
UI STATE
3D SCENE STATE
SERVER DATA
```

Do not force all three into one state model.

## Animation

Use frame-based animation only where necessary.

Prefer event-driven or demand-driven rendering for static scenes.

## Suspense / Loading

3D assets should have explicit loading behavior.

The UI should communicate loading without blocking unrelated content.

## Responsive Behavior

Canvas dimensions and camera framing must adapt to viewport changes.

## Interaction

Pointer events may control:

- object hover
- rotation
- camera movement
- selection

but essential information must remain accessible outside the canvas.

## Cleanup

Unmounting a scene must release:

- geometries
- materials
- textures
- render resources
- event listeners

## SSR / Next.js

WebGL-dependent code should be isolated appropriately from server-only execution.

The exact implementation must follow the project's current Next.js architecture.

## Acceptance Criteria

R3F is introduced only where it reduces complexity or improves the experience relative to direct Three.js implementation.
