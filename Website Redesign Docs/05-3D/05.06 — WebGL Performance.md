# TinyTots WebGL Performance

## Principle

A premium visual experience that makes the website slow is not premium.

## Performance Priorities

```text
PAGE INTERACTION
>
CONTENT LOADING
>
PRODUCT DISCOVERY
>
3D FIDELITY
```

## CPU

Control:

- JavaScript execution
- animation loops
- event handlers
- React updates
- unnecessary scene calculations

## GPU

Control:

- draw calls
- texture size
- shader complexity
- post-processing
- transparency
- particle counts
- shadow complexity

## Memory

Control:

- texture duplication
- unused assets
- large environment maps
- scene duplication

## Rendering

Prefer:

- demand rendering where possible
- paused scenes when hidden
- reduced resolution when appropriate
- lower-quality mobile configurations

## Visibility

A 3D scene outside the viewport should not consume the same rendering budget as an actively viewed scene.

## Asset Optimization

Evaluate:

- geometry compression
- texture compression
- texture dimensions
- number of materials
- number of meshes

## Mobile

Mobile should have a deliberately reduced 3D budget.

Possible changes:

- fewer meshes
- lower texture resolution
- reduced shadows
- simplified materials
- lower pixel ratio
- reduced animation frequency

## Network

3D assets should be:

- lazy-loaded where possible
- cacheable
- split by experience
- excluded from routes that do not use them

## Measurement

Do not approve performance based only on subjective smoothness.

Measure:

- load cost
- asset size
- render behavior
- frame rate where relevant
- memory behavior
- interaction latency

Exact acceptance thresholds should be established during implementation based on target devices.

## Performance Kill Switch

Every major 3D experience should have a mechanism to disable or downgrade itself if conditions require it.

## Acceptance Criteria

3D never blocks the core shopping journey.
