# TinyTots 3D Usage Rules

## 1. 3D Is Selective

3D should be concentrated in a small number of high-value experiences.

Suggested maximum:

- 1 major 3D hero experience per major campaign
- limited supporting 3D sections
- no default 3D on utility pages

## 2. Content First

Every 3D scene must have an explicit content purpose.

Bad:

```text
Add 3D because the page feels empty.
```

Good:

```text
Use 3D to demonstrate the construction/material/shape of the product.
```

## 3. Interaction First

Interaction should be understandable before the user experiments with it.

## 4. No Forced Interaction

Users must not be required to manipulate a 3D object to access essential information.

## 5. No Hover Dependency

Desktop hover can enhance 3D.

Touch devices must have an equivalent non-hover experience.

## 6. Camera

Camera movement should be constrained.

Avoid:

- uncontrolled orbit
- disorienting camera motion
- excessive perspective distortion

## 7. Lighting

Lighting should maintain product readability.

Never sacrifice product detail for dramatic lighting.

## 8. Materials

Use physically plausible materials when realistic product presentation is intended.

## 9. Backgrounds

Background environments should remain subordinate to the subject.

## 10. Scroll

Scroll-linked 3D should be:

- bounded
- interruptible
- performance-aware

Never make the entire page dependent on continuous WebGL rendering.

## 11. Particles

Particles require a specific design purpose.

Avoid generic floating particles.

## 12. Physics

Physics may be used only where it creates meaningful interaction.

Do not add simulated physics to otherwise static content without a reason.

## 13. Accessibility

Provide:

- static alternative
- reduced-motion mode
- keyboard-accessible surrounding controls
- meaningful text outside the canvas

## 14. Mobile

Mobile may receive:

- simplified scene
- static render
- reduced interaction
- lower resolution
- alternate image

## 15. Failure

If WebGL fails, the page must remain functional.

## Approval Gate

Before implementation, every 3D feature requires:

```text
PURPOSE
+
DESIGN VALUE
+
PERFORMANCE ESTIMATE
+
FALLBACK
+
ACCESSIBILITY
```
