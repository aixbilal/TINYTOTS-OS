# Admin Shell & Navigation

## Purpose

Provide persistent orientation across all management areas.

## Structure

```text
SIDEBAR
├── Dashboard
├── Commerce
├── Marketing
├── Content
├── Customers / Accounts
├── Support
└── Settings

TOP BAR
├── Breadcrumb / Page Context
├── Search where supported
├── Notifications
└── Account
```

Final groups must reflect actual repository routes and permissions.

## Sidebar

Requirements:

- collapsible where useful
- active route clearly visible
- permission-aware
- keyboard accessible
- no hidden critical destinations

## Breadcrumbs

Use where hierarchy is deeper than one level.

## Responsive

Desktop should optimize for operational productivity.

Mobile/tablet must remain functional for important tasks but does not need to reproduce desktop density exactly.

## Global Search

If implemented, search must expose only records the administrator is authorized to access.

## Definition of Done

An administrator always knows:

- where they are
- what they are editing
- how to return
- what actions are available
