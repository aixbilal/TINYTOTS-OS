# Admin States & Permissions

## Purpose

Define the global state and authorization model for the admin frontend.

## Authorization Principle

Frontend visibility is not security.

Every protected operation must be enforced by the backend.

## Permission Model

Use actual roles/permissions from the project's authentication and authorization architecture.

Possible conceptual levels:

```text
VIEW
CREATE
EDIT
PUBLISH
DELETE
MANAGE
```

Do not assume these exist until verified.

## UI Behavior

Unauthorized actions may be:

- hidden
- disabled with explanation
- blocked by route protection

Choice depends on whether discovery of the capability is useful.

## Global States

Every major admin operation should have explicit:

- loading
- success
- empty
- validation error
- permission error
- server error
- offline/network failure where relevant

## Session Expiry

When authentication expires:

- preserve recoverable work where safe
- explain the problem
- provide sign-in/recovery

## Auditability

High-impact actions should be traceable where backend support exists.

## Error Handling

Never expose stack traces, secrets, or internal implementation details.

## Definition of Done

The admin remains understandable and safe under both normal and exceptional conditions.
