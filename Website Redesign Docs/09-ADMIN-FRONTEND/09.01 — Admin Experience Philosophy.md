# TinyTots Admin Frontend — Experience Philosophy

## Purpose

The Admin Frontend is the operational control surface for the TinyTots ecosystem.

It is not a second marketing website. Its priorities are:

1. Accuracy
2. Speed
3. Clarity
4. Safe data manipulation
5. Operational visibility
6. Consistency

## Design Direction

The public website may be editorial and cinematic.

The admin must be:

- calm
- dense where useful
- highly scannable
- predictable
- responsive
- professional

## Core Principle

```text
PREMIUM
≠
DECORATIVE
```

Premium admin design means excellent information architecture and interaction quality.

## Source of Truth

The Admin UI must never invent business state.

Backend/database contracts remain authoritative.

## Global Rules

- destructive actions require appropriate confirmation
- unsaved changes must be protected
- permissions must be enforced server-side
- loading/error/success states are explicit
- tables remain usable at realistic data volumes
- forms preserve user input on recoverable errors

## Motion

Use motion only for:

- navigation
- drawers
- dialogs
- state changes
- contextual feedback

Avoid cinematic effects in operational workflows.
