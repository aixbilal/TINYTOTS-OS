# Admin Tables & Data Views

## Purpose

Define the common data-view system used throughout the admin.

## Table Requirements

Tables should support as needed:

- sorting
- filtering
- pagination
- search
- row actions
- selection
- column visibility
- responsive behavior

Do not implement every feature on every table.

## Density

Default density should support operational scanning without becoming cramped.

## States

Every table needs:

```text
LOADING
→
DATA
→
EMPTY
→
ERROR
```

## Large Data

Use server-side pagination/filtering where appropriate.

Do not load thousands of records into the browser unnecessarily.

## Row Actions

Primary actions should be visible.

Destructive actions should be visually and behaviorally separated.

## Mobile

Use alternative layouts when a wide table becomes unusable.

## Definition of Done

Data remains readable and actionable at realistic scale.
