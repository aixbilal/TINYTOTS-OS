# TinyTots Global UX — Footer

## Purpose

The footer closes the experience while providing reliable navigation and trust information.

## Content Groups

Potential groups:

```text
SHOP
HELP
ABOUT
ACCOUNT
CONTACT
LEGAL
SOCIAL
```

Final links must reflect actual routes.

## Hierarchy

Primary links should be easy to scan.

Do not treat every link as equally important.

## Newsletter

If supported, the newsletter module should have:

- clear value proposition
- simple input
- validation
- privacy/consent handling where required

Do not use unsupported marketing claims.

## Social Links

Only display actual configured social destinations.

## Visual Direction

The footer may be visually stronger than a normal utility footer, but it should remain functional.

Possible premium treatments:

- oversized typography
- editorial imagery
- restrained motion
- strong whitespace

## Mobile

Content groups should collapse into accessible accordions where useful.

## Accessibility

Required:

- semantic navigation
- keyboard access
- visible focus
- meaningful link labels

## Definition of Done

The footer provides a reliable final navigation layer without becoming visually cluttered.
