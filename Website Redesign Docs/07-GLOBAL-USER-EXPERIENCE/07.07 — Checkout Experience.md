# TinyTots Global UX — Checkout Experience

## Principle

Checkout is not an animation showcase.

The priority is:

```text
CLARITY
>
TRUST
>
SPEED
>
VISUAL POLISH
```

## Structure

Typical flow:

```text
CART
↓
CUSTOMER DETAILS
↓
DELIVERY
↓
PAYMENT
↓
REVIEW
↓
CONFIRMATION
```

The actual implementation must follow the project's payment architecture.

## Form Design

Forms should:

- use clear labels
- validate inline
- preserve entered information where safe
- show actionable errors

## Summary

Order summary should remain accessible throughout checkout where layout permits.

## Errors

Never erase user input because of a validation error unless technically unavoidable and clearly explained.

## Loading

Payment and order submission states must clearly communicate that processing is underway.

Do not allow accidental duplicate submission.

## Security

The UI must not invent security claims or display unsupported certifications.

## Mobile

Checkout must be optimized for:

- small screens
- keyboard input
- touch
- autofill

## Motion

Keep motion minimal.

## Confirmation

After successful order creation, communicate:

- success
- order reference
- next steps
- relevant support/contact path

## Definition of Done

A user can complete purchase without encountering unnecessary visual or interaction friction.
