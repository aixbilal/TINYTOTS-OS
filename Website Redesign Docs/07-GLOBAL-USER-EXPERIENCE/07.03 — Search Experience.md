# TinyTots Global UX — Search Experience

## Purpose

Search is a primary product-discovery mechanism.

The experience should feel fast, intelligent, calm, and premium.

## Entry

Search should be reachable from:

- desktop header
- mobile header/menu
- relevant discovery surfaces

## Search Overlay

Preferred direction:

```text
SEARCH
↓
INPUT
↓
RECENT / SUGGESTED
↓
LIVE RESULTS
```

Avoid turning search into a visually overwhelming dashboard.

## Input

Support:

- product names
- SKU where appropriate
- categories
- collection names
- relevant descriptive terms

## Suggestions

Potential sections:

- Products
- Categories
- Collections
- Recent searches

Only show categories that are actually supported by the system.

## Live Results

Results should prioritize:

1. relevance
2. product image
3. product name
4. price
5. availability where appropriate

## Empty State

An empty search should explain what happened and offer useful alternatives.

Example structure:

```text
No results for “...”

Try:
• another keyword
• a category
• a broader search

[Browse all products]
```

## Search Animation

Allowed:

- smooth overlay
- input focus transition
- result reveal

Avoid:

- delayed typing
- heavy blur
- excessive loading animation

## Mobile

Search must remain usable with the virtual keyboard.

## Accessibility

Required:

- labelled input
- keyboard operation
- result announcements where appropriate
- Escape behavior
- visible focus

## Definition of Done

A user can move from search intent to a useful product result with minimal friction.
