# TinyTots Global UX — Notifications

## Purpose

Notifications communicate system feedback without disrupting the shopping journey.

## Types

### Success

Examples:

- item added
- cart updated
- account change saved

### Error

Examples:

- payment failure
- unavailable product
- network error

### Informational

Examples:

- shipping update
- session information

### Warning

Examples:

- stock limitation
- expiring session

## Visual Hierarchy

Notifications should be:

- noticeable
- concise
- actionable where needed

Avoid oversized alerts for minor events.

## Toasts

Use for:

- transient confirmation
- low-risk feedback

Do not use to communicate critical information that disappears too quickly.

## Persistent Alerts

Use when the user must take action.

## Motion

Short:

- enter
- remain
- exit

Respect reduced motion.

## Accessibility

Notifications should use appropriate semantic/live-region behavior where required.

Do not rely only on color.

## Duplicate Prevention

Avoid firing repeated notifications for the same underlying event.

## Definition of Done

Users understand what changed and what, if anything, they need to do next.
