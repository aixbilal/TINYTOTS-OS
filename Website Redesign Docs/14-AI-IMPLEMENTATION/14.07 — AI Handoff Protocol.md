# AI Handoff Protocol

## Purpose

Define how work moves between Gemini, Claude Code/Codex, ChatGPT, and the repository without losing context.

## Core Workflow

```text
DOCUMENTATION
      ↓
GEMINI ANALYSIS
      ↓
IMPLEMENTATION BRIEF
      ↓
CLAUDE CODE / CODEX
      ↓
VALIDATION
      ↓
REPORT
      ↓
REPOSITORY
```

## Gemini → Implementation Agent

Gemini should hand off:

- task
- current state
- target state
- exact files
- relevant documentation
- dependencies
- constraints
- risks
- validation requirements

Do not hand off an enormous unfiltered repository dump when targeted evidence is sufficient.

## ChatGPT Role

ChatGPT can act as:

- design-system reasoning layer
- documentation architect
- task-specification layer
- review layer
- decision support

The implementation agent remains responsible for repository truth and actual code execution.

## Claude Code / Codex Role

The repository implementation agent should:

- verify the supplied file map
- inspect relevant files
- implement
- test
- report

A handoff is not permission to blindly edit every supplied file.

## Handoff Packet

Use:

```text
# TASK

## Objective
...

## Current State
...

## Target State
...

## Relevant Documentation
...

## Exact Files
...

## Constraints
...

## Acceptance Criteria
...

## Validation
...
```

## Verification Rule

The receiving agent must verify important assumptions against the live repository.

## Completion Handoff

After implementation:

```text
IMPLEMENTED
FILES CHANGED
TESTS RUN
BUILD STATUS
KNOWN ISSUES
FOLLOW-UP
```

## Context Efficiency

Pass targeted context.

The goal is:

```text
MAXIMUM RELEVANCE
MINIMUM REDUNDANCY
```

## Final Source of Truth

Once implemented and validated:

```text
GIT REPOSITORY
```

becomes the authoritative implementation state.

Documentation should then be updated when the implementation changes an established architectural decision.
