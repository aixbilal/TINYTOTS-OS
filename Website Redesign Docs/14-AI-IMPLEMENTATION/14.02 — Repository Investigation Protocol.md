# Repository Investigation Protocol

## Purpose

Provide a repeatable method for AI agents to inspect the TinyTots repository before making changes.

## Rule

**Investigate before editing.**

Do not begin implementation based solely on a user description when repository evidence is available.

## Investigation Sequence

### Step 1 — Repository Orientation

Inspect:

- root structure
- package manager
- package.json
- framework configuration
- TypeScript configuration
- styling configuration
- environment conventions
- build scripts

### Step 2 — Route Discovery

Locate the relevant route/page and determine:

- server/client boundary
- layout inheritance
- data loading
- metadata
- child components

### Step 3 — Component Discovery

Search for existing:

- UI primitives
- shared components
- product components
- navigation
- forms
- modals
- animation utilities
- hooks

### Step 4 — Dependency Discovery

Check existing dependencies before introducing new ones.

Especially inspect:

- animation libraries
- icon libraries
- UI libraries
- 3D libraries
- image tools
- state management

### Step 5 — Data Discovery

Trace relevant data:

```text
UI
↓
component
↓
hook/service
↓
API
↓
Supabase/database
```

Do not modify data architecture for a visual requirement unless necessary.

## Investigation Output

Before implementation, produce a concise map:

```text
TARGET ROUTE:
MAIN FILES:
SHARED COMPONENTS:
DATA SOURCES:
DEPENDENCIES:
DESIGN SYSTEM:
RISK AREAS:
```

## Search Rule

Search for existing implementations before creating new ones.

## Safety Rule

Do not perform broad refactors during a focused design task unless explicitly approved.

## Completion Rule

The agent should be able to explain where the requested feature currently lives before changing it.
