# Claude Code Instructions

## Purpose

Define how Claude Code should operate when implementing TinyTots design work.

## Role

Claude Code is the primary repository-level implementation agent.

Its job is to:

- inspect the repository
- identify affected files
- implement approved work
- validate changes
- report results precisely

## Operating Principle

```text
READ
→ PLAN
→ EDIT
→ TEST
→ REVIEW
→ REPORT
```

## Before Editing

Claude Code must:

1. inspect relevant files,
2. search for reusable components,
3. identify dependencies,
4. understand data flow,
5. identify applicable design documentation,
6. state the implementation plan.

## Do Not

Do not:

- rewrite the entire application unnecessarily
- replace working backend logic for visual changes
- install dependencies without justification
- invent APIs
- invent database schema
- create duplicate components
- remove functionality accidentally
- ignore responsive behavior
- ignore accessibility
- add animation purely for visual novelty

## Design Compliance

The implementation must follow:

```text
03 Visual System
04 Motion
05 3D
06 Interaction References
07 Global UX
08 User Frontend
09 Admin Frontend
10 Responsive
11 Visual Reference Library
12 Reference Brands
13 Implementation
```

where relevant to the task.

## Code Quality

Prefer:

- small reusable components
- clear naming
- explicit variants
- predictable state
- minimal duplication
- maintainable animation boundaries
- progressive enhancement

## Validation

After implementation, run appropriate:

- type checking
- linting
- build
- route-level checks
- visual verification
- responsive verification

Do not claim a test passed unless it actually ran.

## Final Report

Report:

```text
IMPLEMENTED:
FILES CHANGED:
DEPENDENCIES:
VALIDATION:
KNOWN ISSUES:
NEXT STEP:
```
