# TinyTots Rejected Interaction Patterns

## Purpose

This document prevents the redesign from accumulating effects simply because they are visually impressive in demos.

## Rejected by Default

### 1. Animation Everywhere

Every section moving independently creates visual fatigue.

### 2. Neon Tech Aesthetic

Strong neon/glow styling conflicts with the intended premium fashion direction unless explicitly approved for a campaign.

### 3. Excessive Glassmorphism

Large numbers of blurred translucent surfaces reduce hierarchy and readability.

### 4. Constant Background Motion

Background particles, blobs, or animated gradients running indefinitely are rejected by default.

### 5. Cursor Dependency

A custom cursor cannot be required to understand or operate the site.

### 6. Hover-Only Information

Important information cannot exist only on desktop hover.

### 7. Scroll Hijacking

Do not replace normal browser scrolling with a custom scroll experience unless there is an exceptional, documented reason.

### 8. Excessive Page Transitions

Navigation should not become slower because of cinematic transitions.

### 9. Fake 3D

Do not add WebGL when CSS transforms or imagery provide the same value.

### 10. Heavy 3D Product Grids

Do not render individual WebGL scenes for every product card by default.

### 11. Infinite Marquees Everywhere

Marquees should not become a generic filler for empty space.

### 12. Excessive Magnetic Elements

Magnetic behavior should be reserved for selected premium interactions.

### 13. Aggressive Text Animation

Do not animate text so heavily that reading becomes slower or unstable.

### 14. Excessive Blur

Blur-heavy effects can create GPU cost and reduce clarity.

### 15. Decorative Loading

Do not make loading slower simply to display an elaborate loader.

### 16. Interaction Without Meaning

If removing an effect does not reduce understanding, delight, or storytelling, question whether it belongs.

## Accessibility Rejection

Any effect that:

- prevents keyboard operation
- removes visible focus
- creates inaccessible contrast
- cannot be disabled for reduced motion
- makes content unreadable

is rejected.

## Performance Rejection

Any pattern that materially damages the core shopping journey without proportional experience value is rejected.

## Final Rule

TinyTots should never look like a showcase of UI libraries.

The finished site should look like **one coherent premium brand experience** whose interactions happen to be technically sophisticated.
