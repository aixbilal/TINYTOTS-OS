# Responsive Components

## Purpose

Define how reusable components adapt across viewport and interaction modes.

## Component Principle

Components should respond to available space and interaction capability, not only device names.

## Examples

### Header

```text
Desktop → full navigation
Tablet  → reduced navigation
Mobile  → menu-driven navigation
```

### Product Grid

```text
Wide → more columns
Medium → fewer columns
Small → compact grid
```

### Filter

```text
Desktop → sidebar/toolbar
Mobile → filter drawer
```

### Mega Menu

```text
Desktop → multi-column
Mobile → drill-down/accordion
```

## Component States

Responsive components must preserve:

- loading
- error
- empty
- disabled
- active
- selected

states.

## Avoid

Do not create separate duplicated components solely because the viewport changed unless the interaction model genuinely differs.

## Content

Components must handle:

- long product names
- missing imagery
- different price lengths
- localization growth
- realistic catalog quantities

## Definition of Done

Responsive behavior is encoded into reusable components rather than page-specific patches.
