# Responsive Motion

## Purpose

Define how TinyTots motion adapts to viewport, device capability, and user preference.

## Principle

Motion is part of the experience, but it must never become a usability requirement.

## Desktop

May support:

- richer hover states
- larger transitions
- controlled parallax
- advanced choreography
- selected 3D experiences

## Tablet

Reduce:

- simultaneous animations
- hover-dependent interactions
- heavy particle effects
- unnecessary parallax

## Mobile

Prefer:

- short transitions
- simple transforms
- opacity
- lightweight reveals

Avoid long scroll-driven sequences.

## Touch

Hover animations have no role in essential interaction.

Use tap/press states where feedback is useful.

## Performance

Motion must respect device capability.

Heavy animation should be progressively enhanced rather than assumed.

## Reduced Motion

Respect `prefers-reduced-motion`.

Provide equivalent functionality without:

- large transforms
- continuous motion
- unnecessary parallax
- looping decorative animation

## 3D

3D follows Phase 05 fallback and performance rules.

## Definition of Done

The interface retains TinyTots' premium motion language across devices without sacrificing performance, accessibility, or interaction clarity.
