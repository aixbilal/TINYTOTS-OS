# TinyTots Responsive System — Desktop

## Purpose

Define the desktop composition system for the public website and admin surfaces.

## Principle

Desktop is not simply the largest mobile layout.

It provides the widest canvas for:

- editorial composition
- product discovery
- multi-column layouts
- navigation
- large imagery
- controlled 3D experiences

## Layout

Use a consistent content container system with deliberate full-bleed exceptions.

Conceptually:

```text
FULL-BLEED
├── Campaign / Hero
└── Editorial imagery

CONSTRAINED
├── Product grids
├── Text
├── Forms
└── Utility content
```

Exact widths should come from the design tokens and implementation system.

## Grid

Use a consistent column/grid model across page families.

Do not create arbitrary widths for individual sections unless the art direction requires it.

## Navigation

Desktop may support:

- full primary navigation
- mega menu
- persistent utility controls
- expanded search

## Product Grid

Column count should adapt to available width rather than relying exclusively on fixed viewport breakpoints.

## 3D

Desktop is the primary environment for richer 3D experiences.

Requirements:

- progressive loading
- performance budget
- fallback
- reduced-motion support

## Definition of Done

Desktop layouts feel spacious and premium while remaining information-efficient and technically performant.
