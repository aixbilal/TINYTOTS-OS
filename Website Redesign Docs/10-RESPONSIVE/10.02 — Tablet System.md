# TinyTots Responsive System — Tablet

## Purpose

Define an intentional intermediate experience between desktop and mobile.

## Principle

Tablet is its own composition state.

Do not simply:

```text
desktop → shrink everything
```

## Layout

Prioritize:

- readable content width
- reduced navigation complexity
- adaptive grids
- touch-friendly controls

## Navigation

If full desktop navigation becomes crowded, transition to a simplified navigation pattern before mobile.

## Product Grid

Reduce columns based on available width and card minimum size.

## Images

Preserve important focal points during crop changes.

## Forms

Multi-column desktop forms may collapse into fewer columns.

## 3D

3D should be lighter than the desktop experience where device capability requires it.

## Definition of Done

Tablet users receive a deliberate layout with no cramped desktop elements and no unnecessary mobile restrictions.
